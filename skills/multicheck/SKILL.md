# multicheck — итеративная adversarial-проверка

Не одно ревью, а **цикл** независимых оппонентов. Согласие разных вендоров даёт
уверенность, расхождение — флаг. Три режима:

- **default** — панель ломает код, ты чинишь, цикл повторяется.
- **investigate** — панель опровергает вывод или разбор, а не код.
- **grill** — панель допрашивает автора до того, как он начал.

## Установка и запуск

Скилл самодостаточен: движок (`bin/`, пакет `multicheck/`) лежит рядом с этим
`SKILL.md`. Нужен только Python 3 и ключ OpenRouter — задай `OPENROUTER_API_KEY`
или положи его в `~/.config/multicheck/openrouter_key`. Команды `bin/mc-*` ниже —
**относительно директории этого скилла** (той, что назвал загрузчик как её базу).
Одна сильная модель по умолчанию; `MC_PANEL=cheap` — дешёвая тройка (см. README).

## Scope

Диф по приоритету: аргумент-путь → `git diff --staged` → `git diff` →
`git diff <base>...HEAD`. Пусто — скажи и остановись.

## Цикл (режим default)

**1. Ломаем.** Своими силами — атакуй диф сам: корректность, гонки, крайние
случаи, права доступа, целостность данных. На крупном диффе раздай сабагентам
разные линзы, каждый ломает со своей стороны. Затем независимая панель:

```bash
bin/mc-review /tmp/multicheck.diff
```

**2. Сводим и проверяем.** Дедуп по паре «файл + суть». **Каждую находку сверь
с реальным кодом** — модели не видели контекста и уверенно выдумывают. Ложные
отсей, пометив почему. Оставь подтверждённые.

**2b. Рейтинг — отдельным шагом.** Severity назначает не тот, кто нашёл:

```bash
bin/mc-rate подтверждённые.md
```

Два независимых rater'а оценивают каждую находку по tier × precondition ×
radius, скептик-supervisor консолидирует и выдаёт `severity · verdict · почему`,
где verdict — **KEEP** (чинить), **HARDENING** (нет attack path, не блокирует),
**DROP** (ложняк / уже обработано). Второй барьер против раздутых находок:
supervisor роняет то, что прошло сверку, но не имеет реального пути атаки.
Чиню KEEP по убыванию severity; цикл считается по KEEP.

**3. Решаем, продолжать ли.** Правило остановки — в `multicheck/convergence.py`:

- ноль подтверждённых → **идеал**, выход;
- тот же набор находок, что в прошлом раунде → **зацикливание**: дефект требует
  редизайна, а не правки. Стоп, не молоти;
- число подтверждённых не уменьшилось → тоже зацикливание;
- иначе — чиним дальше, но не больше пяти раундов.

**4. Чиним корень, а не симптом.** Минимальный корректный диф.

**5. Прогоняем линтеры и тесты** на изменённых файлах. Красное от фикса — это
находка следующего раунда.

**6. Пересобираем диф** и идём в следующий раунд.

## Режим investigate

Когда проверять надо не код, а вывод: разбор инцидента, гипотезу, «почему упало».

1. Собери файл: `ВЫВОД: … ОБОСНОВАНИЕ: …` — всё, на чём вывод держится.
2. `bin/mc-refute вывод.md`
3. Валидные возражения либо закрой данными, либо понизь уверенность вывода.
   Цикл до «устойчиво» или «нужны такие-то данные».

Не заявляй вывод фактом, пока панель его не пробила или данные не собраны.

## Режим grill

Перед реализацией — вскрыть слепые зоны.

1. `bin/mc-grill план.md`
2. Задай пользователю самые злые вопросы, по одному-два, дождись ответов.
3. Слабый ответ = дыра в плане. Уточняем до кода, а не после.

В хуке допрос не интерактивен: `GRILL_FAST=1` печатает вопросы как самопроверку.

## Правила своего проекта

Панель ищет общие дефекты. Чтобы она искала ваши — положите файл с правилами и
укажите путь:

```bash
export MC_PROJECT_RULES=~/.config/multicheck/project-rules.md
```

Текст подставится в промт всех трёх режимов. Пишите туда то, что у вас реально
стреляет: запрещённые конструкции, требования к изоляции данных, обязательные
поля. Держите этот файл вне публичных репозиториев.

## Принципы

- Считай код и вывод сломанными, пока не доказано обратное.
- Согласие независимых источников = уверенность, расхождение = флаг.
- Раннее детектирование круга важнее лишних раундов.
- Находки проверяй против кода: уверенный тон модели ничего не значит.
